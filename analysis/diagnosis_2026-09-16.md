# RSX 行走异常排查（2026-09-16）

分析对象：`logs/rsl_rl/rsx_flat/2026-09-15_21-31-03`，最新视频 `videos/train/rl-video-step-34000.mp4`（4.02 秒，50 FPS），以及当前 Python 配置、URDF/STL、本机 Isaac Lab 实现。

## 1. 最新策略没有学到连续行走

TensorBoard 共 1500 次迭代，`Train/mean_episode_length` 的首值、末值和最大值均为 **1 步**。物理步长 0.005 s，decimation=4，每次动作只有 0.02 s 就结束回合。`Episode_Termination/base_contact` 几乎为 1，末值为 1；`Episode_Termination/time_out` 末值为 0；末尾奖励约 -4.011，终止罚分 -200 × 0.02 = -4 占主导。

视频抽帧见 `video_34000_sheet.jpg` 和 `video_32000_sheet.jpg`。画面中的群体位置和方向不断变化，结合日志可确定存在反复重置：每次 reset 又随机平移 x/y ±0.5 m、yaw ±3.14 rad。不能把这些跳变当成正常步态或连续追踪指令。

当前运行中的 WASD 进程加载的正是该次失败训练的 `model_1499.pt`。修改环境配置不能把这个已经失败的权重变成正常行走策略。

## 2. 自碰撞 + 机身接触终止是最高优先级问题

历史配置 `params/env.yaml` 实际使用：

- `enabled_self_collisions: true`
- `collider_type: convex_hull`
- `base_contact`: `body_names: base_link`, `threshold: 1.0`

URDF 的 collision 直接使用完整 CAD STL。机身碰撞凸包与腿部可能发生内部相交。Isaac Lab 的 `illegal_contact` 检查 `net_forces_w_history`，没有区分机身碰地和机身碰自己的腿。

诊断脚本 `probe_contacts.py` 使用 4 个环境、50 个零动作步；控制周期、初始姿态、历史 PD、自碰撞和 1 N 终止阈值与问题相关设置保持一致，关闭观测噪声并固定初始朝向以便对照。它不是完整策略回放。

开启自碰撞时，200/200 个环境步全部终止。首步机身高度仍约 0.3695 m，机身接触力约 **9055–9081 N**；髋部/大腿 link 也出现数千 N 接触力。原始记录：`probe_self_on.json`。这不是正常身体摔到地面的量级和时序。
对照实验仅关闭自碰撞后，首步 4 个环境机身接触力全部为 0 N，均未终止；50 步内终止总数降为 7/200（见 `probe_self_off.json`）。这确认自碰撞是出生即重置的直接原因，但零动作随后仍有倒地，关闭自碰撞尚不足以实现稳定站立。


当前 `rsx.py` 已改为 `enabled_self_collisions=False`，但历史权重不会因此恢复。当前将终止阈值提高到 8 N，也不足以解决约 9000 N 的内部碰撞。

建议先在关闭自碰撞条件下完成稳定站立/短程行走；需要自碰撞时，重建简化 collision、设置必要碰撞排除，并将“机身碰地”与其他接触分开判断。不要只提高阈值或直接删除倒地终止。

## 3. URDF 左右膝关节符号与默认姿态不一致

将 URDF 每级 origin 的 rpy 和 axis 逐级变换到 base 坐标系，而不是只看 axis 字段，零位下得到：

| 关节 | 左腿 | 右腿 |
|---|---|---|
| 1 髋 pitch | -Y | -Y |
| 2 髋 roll | +X | +X |
| 3 腿 yaw | +Z | +Z |
| 4 膝 | **+Y** | **-Y** |
| 5 踝 | +Y | +Y |

当前默认两腿均设髋 0.15、膝 0.30、踝 -0.15 rad。左脚相对于 CAD 零位净旋转约 0，右脚净旋转约 -0.60 rad（-34.4°）。根据真实 STL 顶点计算，当前姿态脚部世界 x 范围为左 `[-0.04279, 0.11201]` m、右 `[0.06403, 0.20428]` m，明显不是对称预蹲。

两膝同时使用 `[-0.1745, 2.2689]` rad 限位，也意味着它们被允许朝相反物理方向大幅弯曲。若要对称前向屈膝，可统一膝关节正方向，再统一默认角和限位；具体候选是将右膝 `leg_r4_joint` 的局部 axis 从 `0 0 1` 改为 `0 0 -1`，使其与左膝一致。但应先做单关節可视化及硬件正方向核对，此报告未改 URDF。

如果选择保留原始 joint axis，则要相应调整另一侧默认角、限位、控制符号，不能只把 0.3 改成 -0.3 而保留现有限位。比如 -0.3 已超出当前下限 -0.1745。

## 4. 初始高度让脚底穿地约 9 mm

在默认 base_z=0.36 m、当前默认关节角下，STL 脚部最低点：左 -0.00879 m，右 -0.00847 m。机身本身最低点约 +0.25582 m，初始机身并未碰地。

应先修正对称默认姿态，再根据修正姿态的碰撞几何最低点重新设置出生高度并保留数毫米间隙。0.37–0.38 m 只能作为当前几何的检查范围，不是完成姿态修正后可直接套用的最终值。

## 5. 当前代码与权重训练时配置不一致

| 项目 | 最新权重训练时 | 当前代码 |
|---|---|---|
| 自碰撞 | true | false |
| solver position iterations | 8 | 4 |
| RS06 Kp/Kd | 200 / 5 | 60 / 3 |
| RS02 Kp/Kd | 180 / 4 | 50 / 2.5 |
| RS00 Kp/Kd | 20 / 2 | 20 / 2 |
| base_contact 阈值 | 1 N | 8 N |

| 转向命令 | heading 控制，限幅 ±0.5 rad/s | 恒为 0 |
| 站立环境比例 | 0.02 | 0.5 |

本机 play/play_wasd 脚本加载注册任务的当前配置，并非自动恢复 checkpoint 旁边的 env.yaml。用当前环境加载旧权重，会改变策略所面对的执行器和命令分布。

最新训练原本覆盖了 1 m/s，因此不能把最新视频失败归咎于“1 m/s 超出当时训练范围”；它主要受单步终止影响。对于以后使用当前配置训练的策略，PLAY 的 1 m/s、WASD 的 W=1 m/s、A/D=±0.5 m/s、Q/E=±1 rad/s 才是训练范围外指令。最新旧模型也没有学习侧移，转向训练范围只有 ±0.5 rad/s。

当前 PLAY 还继承 50% 随机站立，普通 play 中部分环境会被置为零指令。WASD 脚本主动清零了 rel_standing_envs，不受这一项影响。WASD 在更新 command 后使用上一帧 obs，另有约一控制周期的指令滞后，但这不是严重乱动的主因。

## 6. 电机和奖励的次级问题

DCMotor 的真实力矩裁剪还受 `effort_limit` 约束，`saturation_effort` 不会覆盖它。当前和历史 RS06/02/00 的低速输出上限分别是 11/7/5 N·m，而不是 URDF 标注的 36/17/14 N·m。这不自动意味着配置错误：连续额定力矩限制可能是有意选择，但必须明确目标电机模型。

历史 Kp=200/180，在静止且忽略阻尼时，仅约 0.055/0.0389 rad 位置误差就达到 11/7 N·m 上限；action scale=0.25，初始探索 std=1，足以频繁进入饱和。降低 Kp 后需要重新训练，不能直接假设旧策略保持性能。

URDF 总质量约 12.6809 kg；不应只凭视觉体积判断电机足够或不足。需要记录实际 applied/computed torque、关节速度和饱和比例后再调参。

`joint_deviation_hip` 从上一轮 -0.1 提到 -1.0，可能过度限制髋 roll 的侧向重心转移；`dof_pos_limits` 只约束踝，`dof_acc_l2` 和 flat 的力矩罚项仅选 1–4 号关节、漏掉踝。应在碰撞/姿态修正后再评估这些奖励，不要把它们当作单步终止的首因。

当前 50% 站立、运动速度均匀分布 0–0.3 m/s，而 `feet_air_time_positive_biped` 仅在平移命令范数 >0.1 时启用：约只有总环境的 1/3 能获得该步态奖励。速度跟踪 std=0.5 时，0.3 m/s 命令下静止仍有 exp(-0.3²/0.5²)≈0.698 的线速度奖励，0.1 m/s 时约 0.961；存在偏好站立的可能，需通过确定性评估验证。

本机 DCMotor 源码为主要依据；语义也见 Isaac Lab 官方文档：https://isaac-sim.github.io/IsaacLab/main/_modules/isaaclab/actuators/actuator_pd.html 。

## 7. 上一轮可作对照，但不能直接宣称正常行走

`2026-09-15_21-17-16` 末尾平均回合达到 1000 步（20 s），超时结束比例约 99.5%；最新一轮只剩 1 步。两轮差异包括：开启自碰撞、solver 4→8、action scale 0.5→0.25、髋偏移惩罚 -0.1→-1，以及收窄侧移/转向命令。

## 建议处理顺序

1. 保留失败日志作证据；不要继续用 `21-31-03/model_1499.pt` 判断配置修复后的行走能力。
2. 修正膝关节符号约定与默认姿态，重新计算出生高度；验证零动作能稳定支撑。
3. 先关闭自碰撞完成基线，后续为 CAD 模型建立合适的碰撞体和接触过滤。
4. 固定训练/播放使用同一机器人参数；从 0、0.1、0.2、0.3 m/s 无噪声前向命令评估，记录连续回合长度、真实速度、倾角、足底接触与力矩饱和。
5. 重新训练；站稳并有稳定前向跟踪后再逐步加入转向、侧移、随机扰动和自碰撞。

本次未修改生产训练代码、URDF 或既有 checkpoint。新增的 analysis 文件用于复现和保存证据。
