# RSX 步态奖励调参方法论

本文记录"看到什么现象 → 判断根因 → 动哪个参数"的思维流程，以及本项目各关键参数的**含义**和**取值依据**。配合 `diagnosis_2026-09-18.md`（一次完整的实战案例）阅读。

---

## 一、核心心法：奖励定义"什么是最优"

强化学习不会"听话"，它只会**最大化奖励**。所以看到坏行为，本质只有两种可能：

- **(A) 最优解本身就错了** —— 坏行为恰好是奖励的全局最大点（例：拖步就能拿满速度分）。
- **(B) 最优解是对的，但够不到** —— 好行为有奖励，但中间是"零梯度的悬崖"，策略爬不过去（例：`landing_overstep` 门槛太严，恒为 0）。

**几乎所有调参都是在判断"现在是 A 还是 B"，然后对症下药：**

- A → 让坏行为不再是最优（**提高任务难度** 或 **给坏行为加惩罚**）。
- B → 把悬崖填成斜坡（**降门槛 / 加密集整形项 / 补上必要的观测 / 加探索**）。

## 二、诊断三件套（调参前必看）

| 看什么 | 回答什么问题 |
|---|---|
| **回放视频** | 现象是什么？（拖步 / 原地踏步 / 前扑 / 抖动 / 摔倒 / 打滑） |
| **TensorBoard 每项 `Episode_Reward/*`** | 哪个项被"刷爆"（farmed）、哪个项"饿死"（≈0 且平） |
| **稳定性指标**：`mean_episode_length`、`Episode_Termination/*`、`action_rate_l2`、`dof_acc_l2` 的量级 | 是不是站不稳 / 动作暴烈 / 抖振 |

> 关键工具就是**每项奖励的分解曲线**。它直接告诉你策略在优化什么、忽略什么。
> 例（2026-09-18 案例）：速度分 0.9、步态分 0 = 典型的 A+B 并发（拖步是最优，且步态奖励够不到）。

## 三、各参数的含义与取值依据

### 速度指令 `commands.base_velocity.ranges.lin_vel_x`（当前 `(0.4, 0.9)`）
- **含义**：任务本身——要求机器人前进多快。这是**最强的杠杆**，直接改变"什么是最优"。
- **依据**：低于 ~0.4 m/s 时拖步就能满足速度（情况 A）。把下限抬到 0.4 让拖步"物理上够不到"，逼出真正的跨步；上限 0.9 留余量但不逼到极限摔倒。

### 步态时钟 `period`（当前 `0.7 s`）
- **含义**：一个完整步态周期时长（左右各迈一步）。
- **依据（可算）**：每周期前进距离 = `v·T`，一周期两步 → **步长 ≈ v·T/2**。v=0.6、T=0.7 → 步长 ≈0.21 m，腿长约 0.37 m，步长/腿长 ≈0.57，合理人形步幅。另一参照是腿的自然摆动周期 `2π√(L_com/g)` ≈0.8 s，0.7 s 与之接近、学起来省力。
  - 步子**太大/前扑** → 调**小**；**太碎** → 调**大**。

### `stance_ratio`（支撑相占空比 / duty factor，当前 `0.55`）
- **含义**：每条腿一个周期里**着地时间的比例**（物理术语 duty factor）。
  - `>0.5` → 有双脚支撑重叠 = **走**；`=0.5` → 瞬间交换；`<0.5` → 出现腾空 = **跑/跳**。人走路约 0.6。
- **依据**：0.55 给一小段双支撑重叠，最稳，适合先学会走。
  - 交换脚瞬间**站不稳/摔** → 调**大**；想更轻快甚至跑 → 调**小**。

### `offset`（左右腿相位差，当前 `0.5`）
- **含义**：两腿错开多少。双足行走**恒为 0.5**（反相交替）；四足才用别的值区分 trot/pace/bound。基本不动。

### `feet_air_time.threshold`（当前 `0.30`）
- **含义**：单步奖励的**封顶值**，等价于"期望的单脚支撑时长"。
- **依据**：要与 period 一致——约等于摆动时间 `(1-stance_ratio)·T ≈ 0.45·0.7 ≈ 0.31`。这样只有**真正一步**能拿满，拖步（接触 ~0.05 s）拿不到。原值 0.40 偏大、又因拖步进不了单支撑相而恒 ≈0。

### `gait_contact.weight`（当前 flat `1.5` / rough `1.0`）
- **含义**：步态结构相对**速度跟踪**（weight=1.0）的重要性。
- **依据**：权重**只看相对比值**。`gait_contact` 每步最高 ~2、速度每步 ~0.9，故 1.0 权重让两者量级相当、足以把策略从拖步拽走，又不压过速度。
  - 仍**无视步态在拖步** → 调**高**；**原地踏步/牺牲速度对时钟**（`track_lin_vel_xy` 掉了）→ 调**低**。

### `landing_overstep.weight`（30 → 当前 `6`）
- **含义**：带门槛的**稀疏加分项**（成功跨步才给）。
- **依据**：通用铁律——**稀疏/门槛型 bonus 绝不能是最大的项**。原 30 让它独占 22.76/384、带崩速度与平滑度（farming）。降到 6 只做锦上添花，主驱动交给密集的 `gait_contact`。

## 四、"看到现象 → 动哪个参数" 速查表

| 现象 | 先看的信号 | 判断 | 动作 |
|---|---|---|---|
| **小碎步/拖步** | 速度分高、步态分≈0 | A：拖步即最优 | ↑ 速度指令；↑ 步态项权重 |
| **原地踏步、不前进** | 步态分高、速度分低 | 步态项压过速度 | ↓ 步态项权重；↑ 速度指令权重 |
| **某加分项爆表、其它项崩** | 单项占比 >50% | farming | ↓ 该项权重 / 收紧门槛 |
| **步子太大/前扑摔** | — | 步频太慢 | ↓ period |
| **步子太碎** | 步态分不满 | 步频太快 | ↑ period；↑ air_time threshold |
| **交换脚瞬间摔** | 终止率↑ | 双支撑不足 | ↑ stance_ratio |
| **抖振/动作暴烈** | `action_rate`/`dof_acc` 量级大 | 控制不平滑 | ↑ action_rate/dof_acc 惩罚；查 armature、Kp/Kd |
| **一直单步终止/出生即倒** | 终止率≈1、回合长≈1 | 物理/初始姿态问题 | 查碰撞、初始高度、PD（见 09-16 报告），**别调奖励** |
| **好行为奖励恒为 0 且平** | 该项曲线贴地 | B：够不到 | 降门槛 / 加密集整形 / 补观测 / ↑ entropy 探索 |

## 五、调参纪律（避免越调越乱）

1. **一次只动一个变量**（或一组强耦合的，如 period 与 threshold 一起动），否则无法归因。
2. **权重看比值，不看绝对值**：先估每项"每步的典型量级"，再想它相对主任务项该占几成。
3. **改完必对比同一张 TensorBoard 面板**：看目标项有没有涨、代价项有没有崩。
4. **先稳定，再步态，再花样**：能站 → 能走直线 → 再加转向/侧移/扰动。顺序反了会互相干扰。
5. **区分"奖励问题"和"物理问题"**：回合长恒为 1、出生即倒是碰撞/PD/姿态的事，**调奖励没用**——最容易踩的坑。

---

## 六、一句话总结

> 先用**视频**命名现象 → 用**每项奖励曲线**判断是"最优解错了(A)"还是"够不到(B)" → A 就提高任务难度或加惩罚，B 就把悬崖填成斜坡 → **一次动一个、重训、对比同一张图**。
> 参数只是这套判断的落点，真正的能力是读懂那张奖励分解曲线。
